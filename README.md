# OMS 动销预测与可测性分析

这是一个基于 Python + Streamlit 的团队项目 Web 应用，用于从本地 SQLite 数据库中读取 OMS 销售汇总数据，按不同业务粒度进行动销预测、滚动回测和可测性分析。

当前使用数据表：`adb_model_sales_summary`。

字段映射：

| 业务含义 | 数据库字段 |
| --- | --- |
| 时间字段 | `fin_year_month` |
| 渠道大类 | `channel` |
| 渠道细分类 | `channel_` |
| 型号 | `product_model` |
| 品类 | `product_category` |
| 细分类 | `product_class` |
| 动销预测目标 | `qty_total` |

重要说明：当前以 qty_total 作为动销数量口径，最终项目交付前需要与业务方确认该字段是否与动销定义完全一致。

## 数据库路径

数据库只保存在本地，不复制到本目录，不硬编码任何同学的个人目录。应用默认从环境变量 `OMS_SQLITE_PATH` 读取数据库路径。

PowerShell 示例：

```powershell
$env:OMS_SQLITE_PATH="D:\Code\xhkp\202321101019\任务五\oms_sales_data.sqlite"
```

也可以在 Streamlit 页面左侧边栏手动输入数据库路径。

## 三种预测粒度

1. 渠道大类预测：按 `channel + fin_year_month` 汇总 `qty_total`。
2. 渠道细分类预测：按 `channel + channel_ + fin_year_month` 汇总 `qty_total`。
3. 渠道型号预测：按 `channel + channel_ + product_model + fin_year_month` 汇总 `qty_total`。

渠道型号层级可能对象很多，应用默认只分析筛选条件下按总动销排序的前 50 个对象，并提示继续筛选，避免一次性读取和计算全量型号。

## 模型选择逻辑

候选算法包括：

* Naive 最近值预测；
* 三期移动平均；
* 简单指数平滑 SES；
* Holt 线性趋势；
* 线性回归趋势预测；
* Seasonal Naive；
* Random Forest 滞后特征预测；
* Croston SBA 间歇性需求预测。

自动选择使用 Walk-Forward 滚动回测：

* 默认最少训练期：12 个月；
* 默认回测窗口：最近 6 个完整月份；
* 预测步长：1 个月；
* 不随机打乱时间顺序；
* 自动排除疑似最新不完整月份。

评价指标以 WAPE 为主，辅助参考 sMAPE、MAE、Bias。若真实值总和为 0 导致 WAPE 无法计算，则使用 MAE 作为主比较指标。若主指标差异很小，优先选择 sMAPE 更低的模型；若仍接近，选择更简单、稳定的模型。

页面会在预测图之前展示“自动模型选择说明卡片”，包括最优算法、主指标、WAPE、sMAPE、MAE、Bias、回测窗口数量和选择原因。候选算法表会保留未启用或不适用的算法，并说明原因，例如历史不足、季节性不足、非间歇序列或非零样本不足。

## 评价指标含义

| 指标 | 显示格式 | 含义 | 业务解释 |
| --- | --- | --- | --- |
| WAPE | 百分比 | 整体加权绝对百分比误差，越低越好。 | 更适合比较总体预测偏差；真实值总和为 0 时不可计算。 |
| sMAPE | 百分比 | 对称平均绝对百分比误差，越低越好。 | 用于辅助比较不同规模序列，能缓和极大值影响。 |
| MAE | 数量值 | 平均绝对误差，单位与动销数量一致。 | 表示平均每个回测月份大约错多少动销数量。 |
| Bias | 百分比 | 预测偏差方向。 | 正值表示整体高估，可能带来库存或目标过高风险；负值表示整体低估，可能带来备货不足或机会损失风险。 |

## 经验预测区间

应用会基于最佳模型的滚动回测残差生成经验预测区间：

* 残差定义为 `实际值 - 预测值`；
* 使用残差的 10% 分位数作为经验下界调整量；
* 使用残差的 90% 分位数作为经验上界调整量；
* 未来点预测加上上述分位数后得到经验下界和上界；
* 下界会裁剪为不小于 0。

该区间是经验预测区间，不代表准确率保证。如果有效回测窗口不足，页面会提示“历史回测不足，暂不提供预测区间”。

## 可测性定义

可测性表示当前数据对预测的支撑程度，不是对预测准确率的保证。实际预测可信度应结合滚动回测误差、业务节奏和最新数据完整性共同判断。

可测性模块会计算并展示：

* 历史月份数、有效月份数、缺失月份比例；
* 零动销比例；
* 动销均值、标准差、CV；
* ADI、非零需求 CV²；
* 异常值比例；
* 季节性强度和趋势强度；
* 最新完整账期；
* 最佳模型的 WAPE、sMAPE、MAE、Bias；
* 回测窗口数量和误差稳定性；
* 结构质量得分、回测表现得分、综合可测性得分和等级；
* 风险提示列表。

风险提示覆盖历史月份不足、零值比例过高、波动过大、回测误差偏高、最新月份疑似不完整、季节性不足、冷启动或新品风险。

## 数据安全

数据库包含重要业务数据，不得提交到 Git 或推送到远端仓库。应用只使用只读 SQLite 连接，并开启 `PRAGMA query_only = ON`。页面和脚本不输出客户名称，也不展示原始交易明细数据。

## V2.1 智能分析助手

根目录 `app.py` 的“智能分析助手”页签提供规则驱动分析能力。助手会复用左侧 sidebar 当前选择的预测层级、渠道大类、渠道细分类、型号、预测步长、回测窗口和数据库路径，不要求用户重复填写筛选条件。

助手会先检查用户问题中的对象关键词。如果问题写“线下”但左侧筛选为“线上”，默认不会执行预测工具，而是提示用户调整筛选条件。用户也可以主动打开“允许问题中的渠道条件覆盖当前筛选”，让问题中的“线上/线下”覆盖当前 context。

## V2.2 LLM 增强解释模式

V2.2 在 V2.1 规则驱动 Agent 之上增加“LLM 增强解释”模式。LLM 只用于业务解释与报告表达，不直接预测、不直接读取 SQLite、不直接生成数值事实。

LLM 的职责边界：

* 可以基于本地工具输出解释趋势、模型选择、风险和后续追问；
* 不能生成 fact pack 中不存在的预测值、月份、百分比、金额、模型名称或可测性分数；
* 不能声称保证准确率；
* 不能要求用户上传客户明细、数据库文件或原始交易数据；
* LLM 输出必须通过事实一致性校验，否则页面自动回退到 V2.1 规则驱动结果。

### 环境变量配置

默认情况下无需配置 LLM，系统使用规则驱动模式：

```powershell
$env:LLM_MODE="rule"
```

如需启用 LLM 增强解释，设置：

```powershell
$env:LLM_MODE="llm"
$env:LLM_API_KEY="不要提交真实 Key"
$env:LLM_BASE_URL="https://your-openai-compatible-endpoint/v1"
$env:LLM_MODEL="your-model-name"
$env:LLM_TIMEOUT_SECONDS="20"
```

也可以参考根目录 `.env.example` 管理本地配置；运行应用前需要把变量加载到当前 Shell 环境中。不要提交 `.env`。`.gitignore` 已忽略 `.env` 和 `.env.*`，只允许提交 `.env.example`。

### 为什么不能提交 API Key

API Key 属于个人或组织密钥，提交到仓库会造成费用、数据和权限风险。代码、日志、README、测试和 `.env.example` 都不能包含真实 Key。

### 为什么 LLM 不能直接预测

本项目的预测值、模型选择、回测误差和可测性结论必须来自本地工具和历史数据分析。LLM 不是预测引擎，只负责把已经计算好的事实组织成更易读的业务解释。

### 无 API Key 时如何使用

不设置 LLM 相关环境变量即可。页面选择“规则驱动分析（V2.1）”会完全使用本地规则驱动 Agent；即使选择“LLM 增强解释（V2.2）”，当配置缺失或调用失败时也会自动回退到规则驱动分析。

## 当前局限

* `qty_total` 暂作为动销数量口径，最终交付前必须与业务方确认。
* Random Forest 为项目内实现的轻量滞后特征随机森林，适合可解释演示，不等同于工业级模型库。
* 缺少节假日、促销、价格、区域等外部特征，短期预测主要依赖历史序列。
* 最新月份完整性基于记录数和动销量的启发式判断，仍需结合实际数据入库节奏确认。
